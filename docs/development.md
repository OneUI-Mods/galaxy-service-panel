# 設計と検証

## 対象の実機調査

Android 17 / One UI 9のModemServiceModeで、ServiceModeAppは `com.android.phone` プロセスのActivityです。`keyString=0011` を受け、ListViewとString型のArrayAdapterへ最大102行を流し込みます。行タップは元配列の添字で処理し、純正メニューはタイトルで分岐します。モデムへの送信・Messenger・Handlerは変更しません。抽出APKと画面は `artifacts/research/` のみです。

## 実装の境界

- API 102のonPackageReadyを対象パッケージで判定します。共有電話プロセスの最初のパッケージとは限らないため、isFirstPackageだけでは絞りません。
- 対象ActivityのonCreate/onResume/onPause/onDestroyだけを登録します。Activity全体や電話・モデムメソッドをフックしません。
- Android 16/17のプロファイルは別に保持し、ListViewとArrayAdapterの構造が一致する場合だけ整形します。0011以外は触りません。
- 純正アダプタと行リスナーを保持し、DataSetObserverで表示を追従します。clear/addAll/notifyを次のメインループへ集約し、空の中間通知で画面を消しません。定期ポーリングなし。
- 空行を除いた表示にも元の行番号と原文を保存します。選択直前に純正の現在の行と一致を確認し、純正ListViewへ元番号を渡します。行が変化した場合は押下を実行せず再表示します。
- 複数値の分割は認識済みラベルに限定し、未知の形式は単一値または原文へフォールバックします。値や単位を推測・変換しません。
- 構造化表示と原文表示は同じデータを使います。診断値をディスク、Provider、ログへ書きません。プレビューは架空のサンプルです。
- ModuleUiContextはモジュールのResources/ClassLoaderとホストActivityのwindow tokenを組み合わせ、ホスト側AppCompatとの資源混在を避けます。
- 設定Providerは表示設定のみ公開し、状態更新は自アプリと実際のSamsung電話UIDだけを許可します。設定IPCは専用worker、ビュー操作はメインスレッドです。
- OFFは追加ビューとObserverを外し、純正の子ビュー・LayoutParams・ActionBarを復元します。監視用のActivityフックは再ON用に残ります。
- 整形例外は電話プロセスへ伝播させず次のメインループで復元し、設定側の停止をラッチします。終了履歴の保護は、整形が表示中だった区間の対応するPID・プロセス名・時刻・確認済みクラッシュ理由だけを使います。他画面へ移った時点で監視区間を解除し、手動kill、正常終了、未確認理由、履歴重複は数えません。2分内3回で停止し、明示解除nonceで再開します。

## 検証

JVM試験：空行と選択番号の対応、非メニューの括弧、原文と順序の保持、複数メトリクス、欠損値、未知形式・長文、概要の抽出、クラッシュ時間窓・履歴重複・不明/手動終了・時刻逆行。

2026-10-21、Android 17 / One UI 9のSM-S948Qで署名済みrelease版を検証しました。

- Vectorで推奨対象へ登録し、明示許可を受けて通話がないことを確認したうえで、ユーザー0の電話プロセスだけを読み込み直しました。別プロファイルの同名プロセスはUIDで区別し、停止していません。SystemUI・system_server・ホームのPID、kernel boot IDは検証開始時から不変でした。
- 実際のSIM 1・SIM 2情報への遷移、純正Back操作への受け渡し、画面内の数値更新を確認しました。空行を詰めても選択番号は正しく維持されました。
- 原文タブの元行番号・元文字列と、長押し詳細ダイアログの表示・閉じる操作を確認しました。コピー操作そのものは実機の診断値をクリップボードへ出さないため実行していません。
- ツールバーの純正復元で追加ビューが外れ、元のListView、ActionBar、白い背景とシステムバーへ復元しました。設定アプリから再ONし、同じ電話プロセスで整形を再開できました。
- 設定画面、架空データのプレビュー、検索付きライセンス一覧を確認しました。純正復元後のスイッチが古い表示になる不具合を直し、再表示時の同期を確認しました。
- Service Mode表示中だけクラッシュ監視がarmedとなり、別画面へ移ると解除、戻ると再開することをprivate stateで確認しました。許可された手動再読み込み後も失敗履歴は空で、保護の誤発火はありません。
- 通常shell UIDからProviderの状態を書き換える要求はSecurityExceptionで拒否されました。
- JVM試験13件、lintRelease、assembleRelease、依存ライセンス55件、API 102 metadata、SDK 37、署名とalignmentが成功しました。実機APKのSHA-256も配布用署名APKと一致しました。

最初の実画面確認ではホストThemeの属性IDが混ざり、余白・背景・ヘッダーのコントラストが崩れました。空のモジュールThemeへ必要なstyleだけを適用する方式へ変更し、window tokenはホストのまま維持して解消しています。数値を取り出すGUI試験では原文先頭の空白を考慮しておらず一度失敗し、原文を変更せず試験側を修正しました。途中のprivate state読出しが一度失敗しましたが、再確認とその後の検証では成功しています。

未検証：Android 16実機、他機種・他版、長時間運用、実際の電話プロセスクラッシュからの連続復旧。クラッシュを故意に発生させる試験はしていません。クラッシュの理由・PID・プロセス名・監視時刻の分類はJVM試験、監視の付け外しと手動再読み込みの除外は実機確認です。診断値の意味、精度、更新頻度は純正に従います。

電話、SystemUI、端末の自動再起動処理はアプリに含めません。初回読み込み以外の通常の表示切り替えでプロセス再起動は不要です。

## ソースの書式

Javaはgoogle-java-format、PythonはBlackの100桁を使用します。対象OSごとの記録と表示ロジック、認可・クラッシュ判定を分け、逆コンパイルしたコードは製品へ含めません。
